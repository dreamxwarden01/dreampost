# Isolated attachment renderer

This static application renders one parent-authorized PDF or raster attachment. It has no mailbox, SSO, download cookies, authorization tickets, arbitrary file URLs, or general fetch bridge. PDF.js is pinned to 6.3.289. Only its core canvas API is used; no generic viewer, scripting manager, interactive form layer, annotation links, or embedded-file launcher is loaded. XFA and WASM execution are disabled. PDF parsing uses an explicit module Worker port with no automatic fake-worker fallback.

Build with `PREVIEW_PARENT_ORIGINS` containing the exact allowed mail/share origin(s), separated by commas. The generated `preview-config.json` is public configuration and must not contain secrets. An empty list denies every parent. The deployment may serve an equivalent environment-specific JSON response with `Cache-Control: no-store`.

Host the built directory on its own configured origin, on a different site from mail/download/SSO. The API enforces separation from the mail/download site except for explicitly enabled loopback development. Different ports on one hostname do not isolate cookies. The static host must have no authentication cookies and must not serve application APIs or untrusted uploaded files. The parent validates the origin and current iframe before transferring a private MessagePort. Only file length/type and bounded byte buffers enter the renderer. Closing the overlay closes the bridge and destroys the parser worker.

The build emits `_headers` from the same policy function used by Vite. Production hosting must apply that manifest or its exact equivalent, including the exact `frame-ancestors` allowlist. In particular, use a CSP allowing scripts/workers/connections only to this static origin, image/font blobs as required, and no forms, nested frames, plugins, inline scripts, or JavaScript eval. Vite dev/preview sets these headers. Static platforms that support `_headers` can consume the build artifact; another static server must apply the policy explicitly. Merely serving the `_headers` file as an ordinary file does not install the policy. A build regression verifies the emitted exact parent allowlist and no-eval script policy. The parent iframe permits only `allow-scripts allow-same-origin`, which is safe to use here only because its actual origin differs from the parent's. It has no popup, form, download, or top-navigation sandbox exemptions.

Limits include a 64 MiB absolute preview input cap, 500 PDF pages, 16 million canvas pixels, 8192-pixel dimensions, bounded zoom, a 20-second render deadline, two pending bridge requests, and a 256 KiB maximum bridge range. The parent applies its configured file cap and independent request/byte/concurrency budgets. These are resource controls rather than a claim of immunity to browser or parser vulnerabilities. Raster previews are static; animated inputs display their first frame. Canvas previews do not provide a searchable/selectable PDF text layer. Unsupported/encrypted/over-limit documents remain downloadable through the separate authorized native-download path.

All parser assets, including CMaps, standard fonts, ICC profiles and optional decoding fallback files, are copied from the pinned package into the build. No private real-world PDF is needed for tests; browser QA uses generated synthetic files.
